# Enterprise AI UX Motion Skill 使用说明

这份文档面向团队成员，帮助大家理解 `enterprise-ai-ux-motion` skill 的作用、适用场景和使用方法。

## 这个 Skill 是什么

`enterprise-ai-ux-motion` 是一套面向企业级 AI 产品和 SaaS 工作台的交互动效规范。它用于把静态页面优化成更有层次、更顺滑、更高级的交互体验。

它关注的不是炫技动画，而是让动效服务于业务界面：

- 强化信息层级和空间关系
- 提升 hover、点击、展开、加载等状态的质感
- 让 AI 相关界面显得更智能、更轻盈
- 避免过重阴影、夸张弹跳、霓虹感和游戏化效果
- 确保动效可实现、可维护、性能稳定

## 适用场景

当页面包含以下内容时，建议启用这个 skill：

- 企业 SaaS 仪表盘、工作台、业务卡片
- AI 助手、AI 建议、AI 质检、智能处理流程
- 卡片 hover、按钮反馈、弹窗、抽屉、浮层
- 进度条、圆环进度、数字加载、状态切换
- 玻璃拟态、浅色背景、柔和高光、渐变边缘
- 从 Figma 设计稿生成 HTML 或前端页面时，需要补齐交互动效

不建议用于：

- 游戏、娱乐化强的页面
- 强营销落地页的大型视觉叙事
- 需要夸张转场、强弹跳或高饱和霓虹风格的项目

## 如何触发使用

在任务描述中直接提到 skill 名称即可，例如：

```text
使用 enterprise-ai-ux-motion，给这个工作台页面补充高级交互动效并输出 HTML。
```

也可以在需求中描述具体目标：

```text
优化卡片 hover、数字加载、入口图标微交互和 AI 弹窗动效，让页面更有高级感。
```

如果任务涉及 Figma 页面、组件库或设计系统，通常需要同时提供：

- Figma 页面链接
- 组件库链接
- 目标输出格式，例如 HTML
- 需要重点优化的交互点

## 推荐工作流

1. 先读取 Figma 或现有页面，确认结构和视觉层级。
2. 判断哪些元素需要动效，不要给所有元素都加交互。
3. 先处理基础层级：页面入场、卡片 hover、按钮反馈。
4. 再处理业务动效：数字加载、进度条、圆环、状态变化。
5. 最后处理 AI 动效：建议浮层、呼吸态、轻量流动感。
6. 使用浏览器截图或本地预览验证视觉效果。
7. 如果发现具体问题，把修正规则沉淀回 `SKILL.md`。

## 核心设计原则

动效应该是克制、智能、轻盈的。

推荐：

- 使用 `transform`、`opacity`、`filter` 做动效
- hover 在 140-200ms 内给出反馈
- 卡片只做轻微抬升、柔和阴影和内嵌边缘光
- 页面入场使用分层 stagger，不要所有模块同时出现
- 数字加载只在页面进入时播放一次
- AI 元素可以有轻微呼吸、渐变流动或渐显效果

避免：

- 大面积强阴影
- 负 inset 外扩描边导致边缘错位
- hover 时重新播放进度条加载
- 数字加载时改变原本语义颜色
- 给每张卡片都绑定弹窗
- 强弹跳、强霓虹、彩虹边框、过度闪烁

## 常用交互规则

### 卡片 Hover

卡片 hover 应该体现浮起和聚焦，但不能变得厚重。

推荐组合：

- 小幅 `translate3d` 抬升
- 轻微 scale
- 薄接触阴影
- 柔和蓝色环境阴影
- 内嵌渐变边缘光
- 低透明度反光扫过

注意：不要用 `inset: -1px` 之类的外扩描边做 hover 边框，容易出现圆角错位。

### 数字加载

仪表盘数字可以做 count-up 动效，但必须保持可读性。

要求：

- 页面进入时播放一次
- 不在 hover 时重播
- 保留原本颜色，例如蓝色卡片上的白字必须一直保持白色
- 使用 `font-variant-numeric: tabular-nums`
- 结束时可以有轻微 resolve pulse，不要弹跳

### 进度条和圆环

进度动效表示状态，不表示重复加载。

要求：

- 线性进度条和圆环进度使用一致的色彩语义
- 圆环必须是 ring/donut，不要做成扇形图
- 圆环内部不要额外加描边，除非设计稿明确要求
- hover 只做亮度或高光变化，不重新加载

### 图标

图标必须来自指定组件库，不允许临时编造。

要求：

- Filled 和 Outlined 资产可以共存
- 根据设计稿判断使用哪一类图标
- 业务入口常用 Filled 彩色图标
- 系统提示、箭头、关闭等控件常用 Outlined 图标
- 优先导出 SVG，便于颜色编辑和设计还原
- 不引入随机图标库

### 入口图标微交互

入口图标可以比普通数据卡更有趣一点，但要克制。

推荐：

- 轻微上浮
- 小幅缩放
- 柔和 radial highlight
- 短暂 ring pulse
- SVG 图形轻微旋转或位移

避免：

- 大幅旋转
- 连续循环动画
- 影响其他模块的全局动效

### 弹窗和浮层

浮层应体现空间因果关系。

要求：

- 哪个按钮触发，弹窗就跟随出现在哪个位置附近
- 根据 viewport 自动 clamp
- 空间不足时向上翻转
- 不要每个卡片都默认绑定弹窗
- 关闭、resize 后需要重新计算位置或收起

## 验证清单

交付前建议检查：

- hover 效果能看见，但不过重
- 阴影没有被父级容器裁切
- 描边和圆角对齐，没有错位
- 数字加载没有改变原始文字颜色
- 进度条不会在鼠标移出后才加载
- 圆环不是扇形图
- 弹窗位置跟随触发对象
- 图标来自组件库，且为可编辑 SVG
- 页面在浅色和深色背景下都能看清层级
- 支持 `prefers-reduced-motion`

- 某类进度动效的正确实现
- 某类弹窗定位的交互原则

README 只需要同步面向团队的使用说明，不必记录每一次细节修改。
